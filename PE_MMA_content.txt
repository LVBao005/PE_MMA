Practical Exam
Subject: MMA301 | Semester: FALL 2026
1. Overview
You will build CineList, a small mobile app where each person keeps their own private movie watchlist: title, director, genre and watch status, with an optional rating and notes, and a favorite flag.
This exam describes what the app must do, not how to code it. How you structure the code is up to you, as long as the screen names, the visible texts and the testID names in this document are exactly as written.
2. The application
2.1 Setup
An Expo (React Native) project. It must run with npm install followed by npx expo start using only the Firebase config values from your own Firebase project, read from environment variables or an untracked config file. No key may be written directly in the code.
In your Firebase project: enable the Email/Password sign-in provider (Authentication → Sign-in method), create one test account for the grader, and set up the database as described in section 2.2.
2.2 Database (Firestore)
Design the collection yourself in your Firebase project (Firestore Database) and save the Security Rules you used as firestore.rules in your project. Create one collection named movies that stores everything the app saves. It must have at least the fields below. The field names must be exactly as written, because the grader reads and writes them directly through your Firebase project with the test account; you choose the data types, defaults and indexes.

The database itself must refuse bad data, not only your forms. The grader sends writes that break these rules straight to Firestore with the test account and expects an error each time:
title is required (spaces only does not count) and at most 100 characters.
director is required (spaces only does not count) and at most 60 characters.
genre must be one of the four genres above; anything else is refused.
status must be one of the three statuses above; anything else is refused.
rating, if present, must be a whole number from 0 to 5.
notes is at most 300 characters; a longer note is refused.
the same person cannot save the same title + director twice, even if the letter case differs (for example “Dune” and “dune” by the same director); two different people may save the same movie.
Security rules.
Keep Firestore Security Rules turned on and write the rules yourself so that:
a person who is logged in can see and change only their own rows (read, add, change, delete) and nothing else; every movie belongs to the person who saved it;
a movie whose userId is another person's id is rejected when it is saved;
a visitor who is not logged in can neither read nor write anything.
Allow only the actions the app really needs, and never use an admin/service-account key in the app.
2.3 Screens and what they do
Home (public, first screen)
A header with the app name and, when logged out, a Login button and a Register button. Below it a title (home-title, text CineList) and a short description of the app, with at least three feature cards (for example “Track what you watch”, “Sort by status”, “Rate your favorites”).
When logged in, the app opens directly on the List screen instead, whose header shows the user’s e-mail and a Logout button. After Logout you are back on the Home screen.
Register and Login
Forms with your own messages, not the device keyboard’s default ones. Nothing is shown before the first submit; an error disappears once its field becomes valid. Register has e-mail, password and confirm password; Login has e-mail and password.
With valid input, Register creates a real Firebase Authentication account and shows form-success (text Registration successful); Login signs in for real and goes to the List screen. If Firebase refuses (duplicate email, wrong password) its message is shown in error-auth.

List screen (protected)
This screen is only reachable after a successful Login or Register. While the app is still checking whether someone is already logged in, nothing from this screen is shown (no flash of content, no wrong navigation). A logged-in person sees the screen with list-screen.
A. Add a movie.
A form (movie-form) with: title, director, genre (a list with an empty first choice “Choose genre”, then Action, Comedy, Drama, Horror), status (a list with an empty first choice “Choose status”, then Plan to Watch, Watching, Watched), an optional rating and an optional note. Validation runs when the form is submitted; nothing is shown on first load; each message disappears when its field is valid.

With valid input the movie is saved in Firestore for the logged-in user, appears in the list at once without reloading the screen, the form is cleared, and movie-success shows Movie added. If Firestore returns an error — for example the same title + director was already saved — show it in error-movie and do not add anything to the list.
B. The list.
All the user’s movies in alphabetical order by title (not case-sensitive; equal titles ordered by director). Each movie (movie-item) shows its title, director, genre, status, a favorite toggle (a star button that is “on” for favorites) and a way to open its Detail screen. Toggling the favorite is saved in Firestore and the item updates at once; after closing and reopening the app the list is exactly the same. When there is nothing to show, display movies-empty with the text No movies found instead of the list.
C. Filter, search and summary.
All of these work on what is on screen and update immediately (no button to press):
A genre filter (All, or one of the four genres), a status filter (All, or one of the three statuses), a “favorites only” switch, and a search box that keeps only movies whose title or director contains the typed text (not case-sensitive, spaces at both ends ignored). They all combine (every one that is set must match). A Clear button resets all four. When a movie stops matching because of a change (for example it is un-favorited while “favorites only” is on) it disappears from the list at once.
The summary always describes the movies currently shown: the number of movies (movie-count, plain integer), how many of them are favorites (favorite-count, plain integer) and a breakdown with one row per status that appears, the status with the most movies first (equal counts: Plan to Watch, then Watching, then Watched), each row showing the status name and how many movies it has.
Detail screen (protected)
Opened by tapping a movie in the list. Shows that one movie’s full details (title, director, genre, status, rating, notes) and a favorite toggle. An Edit action switches the same fields into editable inputs with Save and Cancel buttons; the same validation rules and messages as the Add Movie form apply, and Save updates the movie in Firestore and returns to view mode. A Delete action removes the movie (with a confirmation step) and returns to the List screen, and the movie is gone from the list immediately, also after closing and reopening the app.
2.4 Look and feel
The app must be usable on a typical phone screen without any text or button being cut off, overlapping, or requiring sideways scrolling. Keep spacing, font sizes and colors consistent across every screen, and reuse the same components (buttons, inputs, cards) rather than styling each screen differently.
